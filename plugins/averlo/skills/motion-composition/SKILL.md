# Averlo · Motion Composition

Direct a focused surface as a readable sequence, not a collection of entrance
wrappers. Preserve the approved static endpoint exactly.

## Start from static evidence

1. Require a schema-v2 `.template-profile.json` receipt and read
   [`visual-parity`'s focus packet](../visual-parity/references/focus-packet.md).
2. Require a complete committed Static Composition record, a current verified
   Visual Parity packet, and the approved static checkpoint unless the caller
   explicitly bypassed review. Use `$averlo:visual-parity`'s Verify phase with
   the same packet to review motion-off and settled motion-on endpoints; it
   proves static endpoints, not intermediate animation frames.
3. Invoke `$averlo:repository-workflows` before implementation. Select
   Interaction plus every actual composition, shell, catalogue, or route concern.

## Compose the movement

1. State one motion thesis and a compact map for the effective scope: reading
   order, primary progression, supporting vocabulary, stillness, compact
   treatment, reduced-motion behavior, and owner.
2. Inventory the individual effects available from existing motion owners and
   approved Storybook compositions whose literal `parameters.motionComposition`
   has `status: "approved"`. If the current static hierarchy, semantic roles,
   and ordering exactly match a `staticPattern` after product copy and assets
   are removed, apply that established composition treatment: source, effects,
   sequence/relative timing, and reduced-motion behavior. Never substitute a
   treatment because only an effect or broad surface label matches.
3. When no exact static pattern exists, choose the smallest individual-effect
   vocabulary that makes the motion thesis legible. When a repeated static
   arrangement needs coordinated scheduling, a handoff, or another relationship
   that individual effects cannot express cleanly, explicitly suggest a new
   composition candidate rather than sprinkling local effects through the
   surface.
   Keep sources responsible for scheduling and effects responsible for scalar
   presentation; do not add a scheduler, observer, or timing system locally.
4. Preserve input agency, focus, keyboard behavior, reduced motion, and real
   content in the initial DOM. Author compact behavior from compact hierarchy,
   not scaled desktop travel. Measure scroll-linked work before accepting it.

## Promote evidence

After a successful local composition, automatically add or update a neutral
Storybook fixture in the instance. Give it literal `parameters.motionComposition`
metadata and the `backport-candidate` lifecycle required by
`$averlo:storybook-backport`; it remains a candidate until human approval.
Do not transfer it to the canonical template in this workflow.

Verify motion-off, reduced-motion, and settled motion-on endpoints through the
same visual-parity receipt. Review normal playback, re-entry, interruption,
resize, and narrow-width behavior; report any instance-local choreography.
